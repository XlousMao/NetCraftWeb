## Docker 排障（用户 Docker Desktop 环境）

- 现象：`docker compose up -d --build` 拉取 `python:3.12-slim`/`node:22-alpine` 失败，报 `dial tcp [2a03:2880:...]:443 connectex`（IPv6 无效地址 = Docker Hub DNS 被污染）。
- 根因：国内网络访问 Docker Hub 受限，未配置镜像加速。
- 关键教训：**Docker Desktop（Windows）会覆盖 `~/.docker/daemon.json`，且启用 containerd snapshotter 后 daemon 镜像配置不生效**，守护进程跑在 WSL2 VM 里，镜像只能通过 GUI（Settings→Docker Engine）配置。
- 最终方案（已验证跑通）：
  1. 直接从可用镜像源 `docker.1ms.run` 预拉取基础镜像并 `docker tag` 成标准名（python:3.12-slim / node:22-alpine）。
  2. Dockerfile 增加 `PIP_INDEX_URL`/`NPM_REGISTRY` 构建参数（默认官方源），compose 从 `.env` 透传，国内用清华 pypi + npmmirror。
  3. Nginx 加 `resolver 127.0.0.11` + 变量 `proxy_pass` 动态解析上游，修复后端容器重建后 IP 变化导致 502。
- 用户环境：Docker Desktop 29.6.1（Windows），守护进程运行中。
- 最终部署：5 容器全 Up（geap-db/geap-redis healthy），http://localhost/ 全链路 200，本周净利润 3068。

## V2 奶块经济领域重构（NetCraftWeb）

按 V2 规格在现有代码上扩展（未推翻重做），完成 P0+P1+P2 大部分。

**核心成果**：
- 货币体系：CurrencySystem/Denomination/ConversionRule（图遍历换算，1钻石结晶=99钻石，不硬编码）
- RMB：FiatExchangeObservation + FiatService（99钻石块=27.1RMB → 1钻石≈0.0304RMB，按时间点生效）
- Decimal 化：经济字段 Float→Numeric(20,8)，economy_calculator 用 Decimal；时间字段除外
- ItemRole 多角色；维修去掉 currency_cost 改纯 item+quantity
- 副本/维修估值快照补 base_currency_value + fiat_value
- 26 个测试通过（test_currency/rmb/historical_price/repair/dungeon...）
- 前端：货币体系配置页 + Dashboard/副本/物品详情显示钻石+RMB

**关键坑（复用注意）**：
- SQLAlchemy 多外键指向同一表时，relationship 需显式 foreign_keys
- 货币物品（钻石块等）本身无价格，估值要走 CurrencyService.to_base_factor 快路径
- record_price 历史价不应覆盖当前价（当前价=最新 observed_at 的价格）
- Alembic Float→Numeric 在 PG 需 postgresql_using；新增 NOT NULL 列需 server_default
- Pydantic response_model 会丢弃未声明的字段（current_value 需显式加进 schema）
- SQLAlchemy 列名 `metadata` 与 ORM 保留属性冲突，用 `metadata_` + validation_alias

**升级说明**：V1→V2 货币单位从 gold 变钻石，旧数据无法无损迁移，需 `docker compose down -v` 重建（README 已写明）。
